# Genatrix · 功能型 Agent

> 状态：草稿 v0.1 · 2026-09-25 · 待裁决
> 回答的问题：底座之上的功能由谁来写、怎么装、在什么环境里跑、怎么升级，而数据和安全仍然只归底座管。

## 定位

Genatrix 永远是**服务个人的数据和安全底座**。企业和多用户不在考虑之内，以后也先不谈。

底座内置的功能只有三类：

- **连通。** 把邮件、消息、日程、文件这些数据源接进来，归一成 01 号的 Item。
- **理解与整理。** 判级、摘要、检索、人与关系、每日摘要、承诺。
- **安全地运行别人。** 一套受控的环境，让功能型 agent 在里面读它该读的、提它该提的，其余什么都碰不到。

除此之外的具体业务，报税、记账、租房、孩子学校的通知、旅行行程，都不进底座。它们是**功能型 agent**，由用户自己（用自己的大模型）或别人来写，装进来运行。

理由有两条。一，每个人的业务都不一样，我们写不完，也不该替人决定。二，大模型已经能按一份清楚的接口写出一个可用的 agent，门槛在接口，不在写代码的人。我们把接口、边界和运行环境做对，就是把这件事做对。

报税是第一个官方 agent，用和别人完全相同的方式写、装、跑，不内置，没有特权。

## 和 03 号的关系

03 号的 agent 层是核心的一部分：流水线和会话，一层多角色。它照旧。

本文的功能型 agent 是另一种东西：**一个受限的主体**。它有身份、有清单、有自己的一块数据空间，在沙箱里运行，通过核心开的几个窄口子和世界打交道。它借用核心的模型调用和审批，但它不是 agent 层的一个角色，agent 层也不信任它。

03 号的"不做多 agent"说的是核心里不搞多个人格。本文不违反它：功能型 agent 不是人格，是被装进来、被管住的程序。

## 一个 agent 是什么

```
Agent 包
  manifest    清单：身份、读范围、可提议的效果、模型用途、触发、配额
  component   一个 WASM 组件，实现 WIT 接口
  prompts     它用到的提示词，版本化的文本
  fixtures    可选：测试样例，用于安装前与升级时的重放
  hash        以上全部字节的 sha256，是这个版本的身份
```

安装之后，它还有：

```
AgentId       安装时生成，重命名、升级都不变
space         它自己的一块数据空间，在 08 号的加密库里，按 AgentId 隔离
versions      安装过的每个版本的 hash，当前生效的是你批准的那一个
```

id 和名字分开，名字只是显示用。版本以 hash 为准。

## 清单

清单是一份声明式的文件，短到一屏能读完。它是这个 agent 能做什么的**全部**：

| 字段 | 例子（报税） | 说明 |
|---|---|---|
| name / purpose / author | NZ 报税 / 整理发票、按 IRD 的方式记账 / Genatrix | 显示用 |
| reads | 邮件，带 PDF 附件，或主题、发件人命中发票规则 | 读范围，见下 |
| blobs | PDF 的文字 | 能取附件的什么：文字、页面图像，或都不能 |
| proposes | RecordEntry（它自己的空间）、ReminderGST | 能提议的效果 kind |
| model | Extract、Classify、Summarize | 能用的用途，02 号那个封闭枚举的子集 |
| triggers | 读范围内有新 Item；每个 GST 周期结束后第 1 天 | 什么时候被叫起来 |
| quota | 空间 200 MB，单次运行 30 s | 上限 |

没写的就没有。清单漏写一项，结果是这件事做不了，而不是什么都能做。这是 00 号第二条原则"参数就是能力"在 agent 上的落地，也是从 crabtalk 学来的最重要的一条：**能力只因声明而存在**。

**读范围**是一个结构化的过滤：来源、账号、Item 种类、方向、是否带附件、附件类型、发件人或主题规则、时间窗、最高级别。不是任意查询，是字段的组合，界面能逐字翻译给你看。

**触发**只有三种：读范围内有新 Item、你在它的对话里说话、清单里写死的日程。模型不能在运行中创建或修改触发。这守住了 03 号的"不做自主调度"：什么时候跑，是清单和你定的，不是模型。

## 窄口子

agent 和世界之间只有核心开的几个口子，定义在一份 WIT 接口里。每个口子只做一件事：

| 口子 | 做什么 | 边界 |
|---|---|---|
| items.query | 按条件取 Item 的引用与正文 | 条件与读范围取交集，由核心代填 |
| items.get | 按 id 取一条 | id 必须落在读范围内，否则当作不存在 |
| blobs.text | 取附件的文字 | 由核心提取；清单没声明就没有这个口子 |
| model.call | 用某个用途调模型 | 走出境闸门；目标、级别、脱敏都不归它管 |
| space.* | 读写它自己的空间 | 只有自己的，看不到别人的 |
| actions.propose | 提一个待批准动作 | kind 必须在清单里；生成的是 03 号的 Action |
| now | 当前时间 | 由核心给，记入运行记录 |
| log | 写一行运行日志 | 进运行记录，不进 Item |

两条设计：

- **范围由核心代填，不由 agent 传入。** agent 调 items.query 时给的条件，核心先和它的读范围求交集再执行。agent 没有办法表达"读范围以外"，因为这个参数根本不存在。这也是从 crabtalk 学来的：宿主覆盖范围字段，而不是去校验它。
- **一个口子一件事。** 不开一个通用的"发请求给核心"再在里面过滤。通用口子加过滤，过滤写错一行就全开了；窄口子写错一个，只错那一个。

没有网络，没有文件系统，没有子进程，没有环境变量，没有随机数以外的系统调用。agent 想让外面发生什么，唯一的路是 actions.propose，然后等你。

## 运行环境

**WASM 组件，用 wasmtime 运行。** 不开 WASI 的文件、网络、环境变量，只链接上面那几个口子。

为什么是 WASM：

- **默认什么都没有。** 能力是一个个加进去的，而不是一个个关掉的。连接器现在用的 macOS 沙箱是反过来的：默认允许，再逐项拒绝，漏一项就是一个洞。
- **可限量。** 燃料（指令数）、内存、墙钟时间都能设上限，超了就终止。
- **可重放。** 输入相同、now 相同，输出就相同。升级时拿过去的真实输入重放，比较新旧版本的输出，这是后面升级流程的基础。
- **跨平台。** 不绑 macOS 那套已经标为废弃的沙箱接口。
- **语言不限。** 能编译成组件的都行：Rust、JS、Python、Go。编译在作者自己的电脑上做，分发的只有 `.wasm`，朋友的电脑不需要编译器。

每次触发创建一个新实例，跑完即弃。agent 要记住的东西只能放进它的 space。

比较过的另外三条路：

| 方案 | 为什么不选 |
|---|---|
| 独立进程加 macOS 沙箱 | 只在 macOS 上有；默认允许；我们现有的规则里，其余文件仍然可读 |
| crabtalk 的 RISC-V 小虚拟机 | 思路和我们一致，生态太小，写 agent 的人和他们的大模型都不熟 |
| MCP server | 是一个拥有你全部权限的进程。能装一个 MCP server，就等于把整台电脑交给它 |

## 数据空间

每个 agent 一块，在同一个加密库里，按 AgentId 隔离。报税 agent 的账本就在这里。

- 空间里是 agent 自己的表或键值，结构由它定，核心不解释。
- agent 可以声明某张表只增不改，核心用触发器保证，finance 项目的账本就是这么防篡改的。
- 空间里的数据是**派生数据**，级别跟随它读过的最高级别，和 02 号的传播规则一致。报税读的是财务邮件，它的整个空间就是 Secret，任何经过 model.call 的请求都只会到本机。
- 你能在界面上看到每个 agent 的空间占多大、导出它、删掉它。
- agent 之间看不到彼此的空间。第一版不做 agent 之间的数据共享，要做也是经过核心、你同意的一条明确通道，不是互相开放。

## 效果与审批

agent 能提的效果分两种：

- **对外的**：SendMail、SendMessage、CreateEvent。和 03 号完全一样，由连接器执行。清单里没声明，就提不了。
- **对自己空间的**：比如报税的 RecordEntry（记一笔账）。由 agent 自己定义 kind，批准后由核心调用它的 apply 入口执行，apply 只能写它自己的空间。

两种都走 03 号的整套机制：版本、哈希、nonce、一次性令牌、过期、撤回、执行三态。审批页里，每张卡片写明是哪个 agent 提的。

**审批卡片由核心按固定结构渲染。** agent 提交的是结构化数据：标题、若干字段、金额、依据的 Item。页面按固定模板显示，不运行 agent 提供的任何 HTML 或脚本。否则 agent 可以在卡片里放一段脚本，在你的浏览器里把数据送出去，前面所有的边界都白搭。

## 模型调用

agent 调模型只能用 model.call，给一个用途和一段按 03 号信封规则组装好的上下文。它不能选模型，不能选本机还是云端，不能带自己的 API key。

- 核心照常过出境闸门：算级别、查策略、脱敏、记账。
- 你在底座里换了模型，接了自己的本地服务或云端 key，所有 agent 自动跟着用，不需要改一行。
- agent 读到的数据里有 Secret，它的请求就只到本机。这不是 agent 自觉，是闸门强制。

这样，02 号的第一条不变量对 agent 同样成立：不存在从 Item 到云端的路径不经过出境闸门。

## 身份与记录

每次运行是一个 Run，发起者是 `Agent { agent_id, version_hash }`。运行记录和 03 号一样只存引用：它查了什么、调了哪个用途、提了什么动作、日志写了什么。

在界面上，agent 是 Chats 里的一个对话对象（06 号的 party）。打开它，上面是它的统计和它空间里的要点，下面是你和它的对话，以及它提过的动作。你在对话里说的话会触发它，它的回复是它的输出。

## 安装

一个 agent 包就是一个文件，可以是你自己写的，也可以是朋友发来的。第一版不做应用商店。

安装时核心读清单，不运行代码，给你看一页：

```
NZ 报税                                   作者 Genatrix · 版本 3f2a…

能读     Gmail（两个账号）里带 PDF 附件、像发票的邮件
能取     这些 PDF 的文字
能提议   记一笔账（需要你批准）
         GST 到期提醒（需要你批准）
模型     只做提取、分类、摘要；你的财务数据不会离开这台电脑
何时运行 新发票到达时；每个 GST 周期结束后的第一天
不能     联网、读其他数据、发邮件或消息、看其他 agent 的数据
```

你点安装，这个版本的 hash 被记为已批准。

安装、升级、扩大权限这三个接口**只接受回环请求**，已配对的手机也不行。理由和 02 号第 12 条一样：给一段代码开数据权限，和接一个新账号是同一级别的事。

## 升级

agent 会变好：作者发了新版，你用自己的大模型改了它，或者以后它自己提出改进。三种来源走同一条路：

1. **新版本是一个新 hash。** 清单或代码的任何一个字节变了，都是新版本，当前版本继续跑，直到你批准新版。
2. **升级是一个待批准动作。** 审批页上显示：
   - 清单的差异，权限扩大的部分标红；
   - 用你过去真实的输入重放一遍，新旧两版提议的动作和写入的数据差在哪里；
   - 新版带的测试样例是否全部通过。
3. **你批准之后才生效。** 旧版本保留，随时一键回滚。
4. **权限扩大永远不能自动批准。** 第二阶段"代理"的规则批准也不行。

能被 agent 改进的，只是它自己的代码和它空间里的数据，比如"哪个供应商记到哪个科目"的对照表。底座的代码、闸门、审批、别的 agent，它都碰不到。

03 号的"不做自我修改"对核心照旧成立。对功能型 agent，这句话变成：**改动可以被提出，生效永远经过你。**

## 官方 agent 没有特权

我们写的 agent 和别人写的，装法一样、沙箱一样、口子一样、审批一样。

这一条的用处是逼我们自己：如果报税 agent 用这套接口写不出来，说明接口不够，就改接口，而不是给报税开一个后门。后门一旦开了，别人的 agent 迟早会要同一个后门。

## 第一个 agent：NZ 报税

来源是 `../finance` 项目。它的原则和 Genatrix 一致：模型只报数字、不算数字；账本只增不改；写操作只生成待批准的草稿。

| finance 的部分 | 在报税 agent 里 |
|---|---|
| taxcore：金额、复式记账、GST、NZ 税年、来源、发票校验 | 原样编译进组件。它本来就不碰文件和网络 |
| taxrules：规则即数据（`rules/nz/2025-26.yaml`） | 规则文件随包分发，放进 space；更新规则是一次升级，附 IRD 原文出处 |
| taxstore：它自己的 SQLite | 换成 space 里的只增不改表 |
| taxingest：入库、去重、校验、草稿、银行对账 | 改造：发票来自读范围内的邮件，文字来自 blobs.text |
| taxmcp、taxweb | 不要了。工具换成口子，确认换成审批页 |

需要底座补的：**附件文字提取**。finance 从来不解析 PDF，是让外部模型直接读文件；现在的本机模型只读文字，所以核心要能从 PDF 里提出文字，给 blobs.text 用。拍照和扫描件要识别图片里的文字，macOS 自带的 Vision 可以在本机做，放在第二步。

## 第二个 agent：检验接口够不够通用

只有一个 agent 验证不了框架。第二个要选一个和报税完全不同的场景：不记账、不算钱、读的是消息而不是邮件附件。候选：旅行行程（从确认邮件里整理航班酒店，提议建日程），或订阅与续费（找出所有订阅，提醒到期）。选哪个待裁决。

## 给写 agent 的人

写 agent 的人手里多半有一个大模型。框架好不好用，一半取决于那个大模型读不读得懂它：

- WIT 接口是唯一的契约，短而且有类型。
- 清单是声明式的，有 schema。
- 一套本地测试工具：拿假数据或你真实数据的只读快照重放，看它会提议什么，不真正执行任何动作。
- 一份写给大模型看的开发指南，就像仓库里的 CLAUDE.md。
- 报税 agent 的源码就是示例。

## 从 crabtalk 学到的

学的：

- 能力只因声明而存在。
- 一种操作一个口子。
- 宿主代填范围字段，而不是校验它。
- 清单能在不运行代码的情况下读出来。
- 代码按内容哈希识别，授权也算进身份。
- id 和名字分开。

避开的（都是它现在真实存在的问题）：

- 一个以你身份运行、根目录是整个家目录的 shell。
- 本机管理端口没有认证，工具能借它给自己扩权。
- 代码文件不锁 hash，被替换了下一条消息就生效。
- 所有 agent 共用一份记忆。
- MCP 的密钥明文存放，MCP 进程拥有完整权限。

## 明确不做

- **不做企业和多用户。** 一个人，一台设备。
- **不给 agent 网络。** 要对外，只能提动作。
- **不支持 MCP server 作为 agent。** 它是一个有你全部权限的进程。
- **不运行 agent 提供的界面代码。** 卡片和空间视图都由核心按固定结构渲染。
- **不做 agent 之间直接通信。** 第一版每个 agent 只和核心说话。
- **不做应用商店。** 第一版一个包就是一个文件，你决定装不装。
- **不给官方 agent 特权。**
- **不做自动升级。** 升级可以被提出，不能自己生效。
- **不让模型创建触发。** 什么时候跑，写在清单里。

## 与其他文档的接口

- 00 号：定位写进"它是什么"。
- 01 号：agent 空间是派生数据，不是 Item；agent 提的动作和写的数据都能追溯到它读过的 Item。
- 02 号：新增不变量 13 到 19。
- 03 号：Action 的发起者多一种；"明确不做"两条的措辞随本文调整。
- 06 号：agent 作为对话对象；安装页、升级页、卡片的固定模板。
- 08 号：agent 空间在同一个加密库里，随备份、导出、抹除一起走。
- 10 号：新增"底座与 agent 框架"一段。

## 待裁决

1. 官方 agent 没有特权，和第三方走完全相同的路。我主张没有。
2. 运行环境是 WASM 组件（wasmtime），不是进程加 macOS 沙箱，也不是 MCP。我主张 WASM。
3. 安装、升级、扩大权限只接受回环请求，配对的手机也不行。我主张只接受回环。
4. 审批卡片和空间视图由核心按固定结构渲染，agent 不能提供界面代码。我主张不能。
5. 触发只有三种：新 Item、你的消息、清单写死的日程；模型不能创建触发。我主张如此。
6. 卸载时删除它的空间，删除前提示导出。我主张删除，因为留着没有主人的数据是负担。
7. 第二个验证 agent 选旅行行程还是订阅续费。我倾向旅行行程，因为它会用到对外效果（建日程），报税不会；代价是日历连接器要从第二阶段提前。
8. 在路线图上的位置：第一次外部用户之后、第二阶段之前。我主张如此，理由见 10 号。
