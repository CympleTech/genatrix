# Genatrix · 界面与审批

> 状态：v0.5
> v0.5 变更：四个面改为今天、审批、对话、问；时间线与记录退到次级入口；"对话"成为统一的交互模型：每个对话对象（人，将来还有代理）一条对话流，上面是统计与承诺。原来叫"对话"的 agent 会话改叫"问"。
> v0.4 变更：形态改为"一个 daemon，任何设备用浏览器连进来"；网页引入框架与构建步骤，手机优先；非回环访问改为设备配对，取代启动令牌；桌面用壳里的网页视图，不再跳浏览器；"不做移动端"撤回。
> v0.3 变更：前端不用 WebAssembly，改为普通网页；监听地址可配置，非回环需令牌。
> v0.2 变更：级别标记加图标；调低级别改为内联确认；批准绑定版本；形态在 M1 结束时检验。
> 回答的问题：时间线、对话、审批面板长什么样，如何让人信任一个读过你全部数据的 AI。

## 界面要做到的一件事

让你信任它。不是靓，是可信。

信任来自四个可感知的性质，界面的每一个决定都为它们服务：

- **能看见依据。** AI 说的每句话，点一下能看到它依据的原始内容。
- **能分清事实和推断。** 哪些是你的数据，哪些是 AI 的产出，一眼可辨。
- **能看见边界。** 什么出去了、什么没出去、为什么。
- **能反悔。** 批准前能改，批准后能查，标错的能改回来。

## 形态

一个 daemon，跑在一台机器上；界面是它 serve 出来的网页，任何设备用浏览器连进来。这是 00 号"个人数据中心"在形态上的直接含义：手机、平板、另一台电脑，都是看同一个后端的窗口，数据不动。

**桌面上它像一个 App。** 菜单栏图标点开，是壳里的一个网页视图窗口装着这个页面，没有地址栏。手机上加到主屏幕，同样没有地址栏。一套界面，两种壳。菜单栏图标本身仍然是常驻后台的形态：显示同步状态和待批准数量，点进窗口。

**默认只听回环。** 能连上回环的人已经是这台机器上的账号，在 08 号的威胁模型之外，所以回环不要任何凭据。

**连进来要配对，不再是令牌。** v0.3 的启动令牌是明文 HTTP 上的一个共享秘密，自己承认"不是认真的身份认证"。现在换成设备配对：在这台机器上（回环）打开设置页，生成一个几分钟内有效的配对码和二维码；手机扫码打开页面，页面用配对码换一个长期的设备凭据，存在浏览器里，之后每次请求都带着它。设置页列出每台已配对的设备，能吊销。配对码用一次即废。这是 03 号"审批只在本机"那条的前提：已配对的设备算你本人。

**网络边界不在这里解决。** daemon 不做 TLS、不做公网暴露。它绑到一个私有网络的地址上（Tailscale 或 WireGuard 这类，机器和手机在同一张虚拟网里），加密和设备身份由那一层给。启动时把这句话打印出来：这个页面里是你全部的邮件和消息，只把它绑到你信任的私有网络上。08 号的威胁模型相应写明新边界。

**网页有框架和构建步骤了。** v0.3 说"哪天界面复杂到需要框架，再引入一个，那时的判断依据是界面本身"。审批面板、对话页、七步向导、设置页，到了那一天。用 Svelte 加 Vite，产物（一个 HTML、一个 JS、一个 CSS、一份清单）仍然编进核心的二进制，用户看不到 node；构建产物随源码一起提交，所以只装 Rust 也能构建核心。从手机尺寸开始设计，桌面是它的放大版：手机上底部四个入口，桌面上是左侧一列。

后端只提供 JSON 接口，所以换前端不影响后端。v0.3 的原生 JS 版就是这样被换掉的。

## 四个面

不做多层导航。四个入口，每个入口一屏：**今天、审批、对话、问**。手机上是底部四个加"更多"，桌面上是左侧一列。

时间线和记录退到"更多"里，与复核、设置放在一起。它们是档案和审计：按时间倒序的全部 Item、每一次模型调用和每一个动作的记录。它们必须存在、必须完整，因为 02 号"你能审计自己的 AI"靠它们兑现；但它们不是给人日常读的东西。日常读的是"今天"要你做的事、"审批"等你拍板的事、和"对话"里每个人跟你说了什么。

### 今天

打开的第一屏。上面是今日摘要，中间是待批准的动作，下面是系统状态。

**今日摘要**是 03 号每日摘要流水线的产物。形态是分组的要点，不是一篇文章：

```
需要你回复（3）
  · 某人问周四能不能改到下午                        [Telegram · 昨晚 22:14]
  · 某公司发来合同修订版，等你确认第 4 条            [邮件 · 今早 08:02]
  ...
你答应过的（2）
  · 周五前把报价发给某人                            [来源 · 日期]
  ...
值得知道的（5）
  ...
```

每一行右侧是来源和时间，点击展开原始 Item。没有引用的句子标灰并注明"无依据"，这是 03 号定的。

**待批准**是审批面板的精简版，最多显示 5 条，更多去审批页。

**你答应过的**同样是精简版，按到期先后最多显示 25 条，后面一行说还有多少条、去哪看。这一屏是"今天"，不是账目；全部未完成的承诺在各自联系人的页面上。曾经这里返回全部，一次 2350 条、767 KB，而界面每五秒还要为了取一个待批准数量把它整个拉一遍。

**状态**一行：几个账号在同步、最后同步时间、本机模型是否加载、云端开关状态。

### 时间线（次级入口）

全部 Item 按 occurred_at 倒序。这是档案，不是阅读界面，所以在"更多"里。邮件和消息混排，靠来源图标区分。

筛选器只有五个：来源、人、方向、级别、时间。不做标签系统，不做文件夹。搜索框在顶部，全文加向量，结果仍然是时间线的形态，只是被过滤了。

每条 Item 的呈现：

- 作者、时间、来源、级别标记（公开、私人、机密，用三种不显眼的色点）。
- 正文是归一后的 text，点击展开可看原文（Raw 的渲染）。
- 有 Annotation 的，摘要显示在正文下方，用不同的字色和一个小标记，明确是 AI 产出。
- 被编辑过的显示"已编辑"，点开看历史版本。被上游删除的默认隐藏，筛选器里可以显示，显示时有明确标记"对方已删除，本机保留"。这是 01 号那个伦理张力的诚实呈现。


### 审批

见下面"审批面板"一节。它从"今天"的精简版升为一个一级入口，因为这个产品在你每天的使用里，最常做也最要紧的一个动作就是在这里拍板。

### 对话

**对话是这个界面的统一交互模型。** 一个读过你全部数据的 AI，最终是通过一群对话对象和你打交道的：真人，以及将来替你干活的代理。每个对话对象一条对话流，你打开它，看到的永远是同一种形态。

列表：每个对话对象一行，头像、名字、角色标签、最近一条消息的开头、最近时间，按最近往来排序。

打开一个对话对象，是三段：

- **顶部是关于这个对象的事实。** 往来统计（对方发来多少、你发出多少、你通常多快回、始于何时、常用语言、最近十二个月的走势）、你给的角色与笔记、双方之间未完成的承诺。收起时是一行摘要，展开是全部。这些是算术和你自己写的东西，不是模型的观点，07 号定的。
- **中间是对话流。** 按时间正序，最新的在最下面，打开时停在最下面。对方在左，你在右。按日分隔。邮件是带主题的气泡，正文过长时收起、点开看全文；群里的发言照样显示，但标出群名，一眼看出那不是对你一个人说的。往上翻加载更早的。每个气泡点开就是那条 Item 本身，级别、判定、摘要都在那里。
- **底部是回复，但回复要经过你。** 不是一个打字就发的框。按"起草回复"，起草器针对对方最近一条消息写一份草稿，草稿以审批卡片的形式出现在对话流的末尾，你改、你批，批了才发。聊天界面天然让人想打字直接发，但 00 号第五条原则只在"经你批准"这一步兑现，这一步不因为界面形态而省掉。

**将来的代理也是对话对象。** 一个整理你财务的代理，一个替你盯某个话题的新闻代理，它们出现在同一个列表里，用同一种对话流告诉你它发现了什么；你在同一个对话里回应它、纠正它、调教它（"以后这类不用告诉我"），那些话成为它的指令与 07 号的偏好。它们与真人的区别只在两处：顶部的事实换成这个代理的职责、权限和最近的运行记录（03 号）；它发来的每一条都标明是 AI 产出，和 Item 的摘要一样有明确的标记。数据模型里对话对象因此是"人或代理"两种，代理那一种在第一个代理落地时再加进 01 号，不提前造。

推断出来的人物合并，在对话对象的顶部有"推断"标记和一个"拆开"按钮。

### 问

和 agent 的会话：你问关于你自己数据的问题，它分步查找再回答。v0.5 之前这一节叫"对话"，现在"对话"留给上面那个统一模型。它是四个入口里的最后一个，是补充，不是主入口。

- 每条 AI 回复下方是它引用的 Item 列表，可展开。
- 回复中调用了工具，显示为一行折叠的步骤："搜索了 12 条消息，读取了 2 个线程"，点开是 03 号的运行记录。
- 回复中提出了动作，动作卡片内嵌在对话里，形态与审批页一致。
- 每条回复标注这次是本机完成还是云端完成，云端完成的可点开看出境记录。

不做打字机效果以外的任何拟人化。没有头像，没有名字，没有"我很高兴帮你"。它是一个工具在回答。

### 记录（次级入口）

三本账放一起，这是 02 号"你能审计自己的 AI"的界面。

**出境记录**第一屏是一句话和一个数字：

> 过去 7 天，0 字节机密内容离开过这台设备。有 14 次私人内容脱敏后发给了 Anthropic。

下面是列表，每条：时间、目的、级别、去向、决定。点开一条，看到实际发出的脱敏后内容，逐字。

**运行记录**：每个 Run 一条，点开是步骤。

**动作记录**：所有 Action，含已执行、已拒绝、已过期。

## 审批面板

这是整个产品里最重要的一个界面，因为 00 号第五条原则只在这里兑现。

一次一条。不做列表勾选批量批准，第一阶段不做，第二阶段的"代理"模式也是靠规则不是靠勾选。

一条待批准动作的卡片：

```
┌──────────────────────────────────────────────────┐
│ 回复邮件 → 某人 <someone@example.com>              │
│                                                  │
│ 依据                                             │
│   某人 · 今早 08:02 · "合同修订版，请确认第 4 条"    │  ← 点开看原文
│   你 · 上周三 · "第 4 条我们要求..."                │
│                                                  │
│ 为什么                                           │
│   对方等你确认第 4 条，你上周已表明立场，建议回复确认。 │
│                                                  │
│ 草稿                                             │  ← 可直接编辑
│   某人，第 4 条按上周讨论的版本，我这边确认。          │
│   ...                                            │
│                                                  │
│ 本机起草                                          │
│                                                  │
│   [ 批准并发送 ]   [ 改后再看 ]   [ 拒绝 ]           │
└──────────────────────────────────────────────────┘
```

- **依据在草稿之前。** 先看它为什么这么想，再看它想说什么。
- **草稿可直接编辑。** 改完点批准，改动成为一个新版本，你批准的就是眼前这一版，旧版本的批准对它无效。改动被记录，07 号用它学风格。
- **批准只接受你本人。** 审批请求来自回环，或来自一台已配对的设备；带这一版的哈希和页面拿到的 nonce。这些你看不见也不需要看见，它们保证你点的和执行的是同一份东西，而且是你点的。手机上批一下，是这个产品在手机上最有价值的动作。
- **拒绝要理由。** 弹出一个单行输入，可以只写两个字。理由进记录。
- **批准键上写着后果。** "批准并发送"，不是"确定"。
- **本机还是云端起草，卡片上有一行。**
- **过期倒计时。** 卡片角上一行小字"2 天后过期"。

键盘优先：上下切换，回车展开，批准与拒绝各一个快捷键，编辑进入草稿框。处理完 20 条不需要碰鼠标。

## 级别的呈现

三种级别是三个标记，每个标记是色点加一个小图标。列表里只显示标记，悬停或展开显示词和判定来源："机密 · 规则：来自银行域名"。只靠颜色不行，色觉不同的人分不出，图标是必需的，不是装饰。

调级别是点标记弹出三选一。往高调，点了就生效。往低调，选项本身写着后果：不是"私人"，而是"改为私人，之后可能脱敏后发往云端"，点这一行才生效。它不是筛选偏好，是一个有分量的动作，所以要多看一眼；但也不弹模态窗、不要求再点一次"确定"。02 号说了，说清楚，不恐吓。

## 空状态

刚装好、还没接账号的时候，四个面都是空的。空状态要说的话只有一句：接入第一个账号。之后回填进行中，时间线从上往下逐渐填满，这本身就是最好的进度反馈。

## 界面的响应

一台机器上的本机服务，没有网络往返，所以任何一屏慢下来都是我们自己的账。三条约束：

- **界面轮询的东西必须是廉价的。** 状态条每五秒问一次，它只能问能靠索引直接答上来的数字。凡是要扫全量的，要么进缓存，要么不要放进轮询。
- **一屏的代价不随语料增长。** 联系人页是对全部 Item 的算术，它的两趟扫描结果算一次留一分钟；你在页面上能改的东西（角色、笔记）不在缓存里，每次现读，所以改完立刻可见。
- **慢的活不占住接口线程。** 磁盘遍历、全量扫描这类同步工作放到专门的线程上去做，否则一条慢查询会连带拖住不碰数据库的请求，连页面本身都加载不出来。

## 语言

界面中英文双语，跟随系统。你的数据是什么语言就显示什么语言，AI 产出跟随对应 Item 的语言，摘要用界面语言。

## 设置

第五个入口，放在导航的末尾，不算"面"：账号与同步状态、模型状态、已配对设备与配对二维码、数据目录与占用、09 号的备份、导出、删除。它是 09 号里那些按钮住的地方。

## 通知

只有一种：有新的待批准动作时，菜单栏图标上出一个数字。不推送，不弹窗，不发声。每日摘要生成后不通知，你打开的时候它在那里。手机上也不推送；Web Push 要 HTTPS 和一个推送服务商，两样都不在第一阶段。

## 明确不做

- **不做原生手机应用。** 手机用浏览器，加到主屏幕。v0.4 撤回了"不做移动端"：形态本身就是任何设备连进来。
- **不做 TLS 和公网暴露。** 私有网络那一层的事。
- **不做主题、皮肤、布局定制。**
- **不做标签与文件夹系统。** 五个筛选器加搜索。
- **不做批量批准。**
- **不做任何拟人化。** 没有名字、头像、情绪。
- **不做仪表盘式的图表。** 记录页是列表和一句话，不是饼图。

## 与后续文档的接口

- 01 号：已编辑、已删除的呈现；对话对象（人，将来加代理）。
- 02 号：出境记录页；级别色点与调级提示；"本机完成"标记。
- 03 号：审批卡片的字段；运行记录的步骤呈现；"无依据"标记。
- 05 号：账号状态、回填进度、重新登录。
- 07 号：对话对象顶部的资料卡；改稿与拒绝理由的采集；对代理的调教成为偏好。
- 09 号：首次运行流程复用同一套界面。

## 已裁决（2026-09-14，全部按建议通过）

1. 前端用普通网页，不用 WebAssembly。2026-09-15 定，理由是这个界面没有需要它的计算。v0.4 加了框架和构建步骤，仍然是普通网页。
2. 菜单栏图标加浏览器，而不是独立窗口。我主张菜单栏。v0.4 改为菜单栏图标加壳里的网页视图窗口：形态没变，少了一次跳浏览器。
6. 一个 daemon、任何设备用浏览器连进来；非回环访问靠设备配对，网络边界交给私有网络。v0.4 定。曾考虑用 gpui 做原生桌面客户端，否决：手机上没有它，两套界面一个人维护不起。
3. 审批一次一条，不做批量。我主张不做。
4. 没有任何拟人化。我主张没有。
5. 调低级别的确认内联在选项文字里，不弹窗。我主张这样。
