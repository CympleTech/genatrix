# Genatrix · 模型层

> 状态：草稿 v0.2 · 2026-09-13 · 评审后修订，待复核
> v0.2 变更：质量分附版本与硬件；沙箱可行性进技术验证；vendor 的配套义务；凭据引用 02 号的绑定格式。
> 回答的问题：本机与云端模型如何接入、如何路由、如何保证本机推理确实不出网。

## 模型是资源

Agent 层请求的是角色，模型层负责把角色变成一次具体的推理。模型换代、厂商更替、本机与云端切换，全部在这一层内部消化。

## 角色

第一阶段的角色，每个角色一句话说清它干什么、允许在哪里跑：

| 角色 | 做什么 | 允许位置 | 输出形态 |
|---|---|---|---|
| classifier | 敏感判级、类别判定 | 仅本机 | 枚举 |
| extractor | 抽取承诺、日期、人物 | 仅本机 | 受约束结构 |
| embedder | 向量化 | 仅本机 | 向量 |
| summarizer | 单条与分组摘要 | 本机；私人内容脱敏后可云端 | 带引用的文本 |
| drafter | 起草回复 | 本机；私人内容脱敏后可云端 | 文本 |
| planner | 会话里的规划与工具选择 | 本机；私人内容脱敏后可云端 | 工具调用 |

"允许位置"来自 02 号的任务级策略，这里只是把它落到角色上。classifier、extractor、embedder 读的是全量数据，永远本机，这一条不是配置项。

## 注册表

一个文件，列出可用的模型和它们的属性：

```
Model {
  name
  location:        Local | Cloud { provider }
  context_length
  tool_protocol:   Native | Structured | Constrained
  supports_vision
  roles:           [角色]                 // 这个模型可以扮演的角色
  cost:            每千 token 的估算，本机为 0
  quality:         按角色的评分，附评测集版本、硬件、日期。裸分数没有意义
}
```

角色到模型的映射是一条链：首选，然后是回落。例如 drafter 的链可以是"云端模型 A → 本机模型 B"，闸门拒绝云端时自然回落到 B。链的每一环都受 02 号策略约束，配置里写了不允许的组合，启动时报错，不是运行时出错。

## 两个进程

模型层是两个进程，不是一个。

```
genatrix-infer     本机推理。加载权重，跑推理，只听本机 socket。没有网络。
genatrix-llm       网关。收核心的请求，按凭据路由到 infer 或云端 provider。
```

分开的理由是 02 号那条"本机模型没有网络"的承诺。一个进程既跑本机推理又连云端，这条承诺就只能靠代码正确性保证。分成两个进程，infer 用操作系统的沙箱剥掉网络能力，承诺变成操作系统在保证。

具体手段：macOS 上用 sandbox 配置文件启动 infer，禁止一切出站网络，只允许读模型目录和监听一个 unix socket。模型权重的下载由核心完成，infer 从不需要网络。这个手段在 macOS 上有个不体面的地方，那个沙箱工具官方标记为过时，但它至今可用且被广泛依赖。如果它某天消失，退路是网络扩展或者在 infer 里用系统调用级别的过滤。这是一个需要持续关注的技术风险，写在这里而不是藏起来。

沙箱能否在阻断全部出站网络的同时，不影响 unix socket 监听与内存映射加载几 GB 的权重，是 10 号技术验证的第一项。验证不通过，两进程方案要改，"操作系统保证"这句话也要撤回，如实改成代码保证。

## 网关

网关就是 crabllm 的库嵌进我们自己的二进制。评估结论在另一份记录里，这里只说我们做什么：

- 嵌入 crabllm-proxy 和 crabllm-provider，得到 OpenAI 与 Anthropic 两种方言的接口、重试、流式、工具调用的中间表示。
- 不用它的发布二进制，因为那个二进制没有链接本机推理，也没有我们要的策略层。
- 每个 provider 打 `local` 或 `cloud` 标签。
- 每个到达网关的请求必须带闸门签发的放行凭据。凭据绑定请求字节的哈希、目标、目的、级别、一次性 nonce 与过期时间，格式在 02 号。cloud provider 拒绝没有凭据、凭据不匹配、或级别不是 Public、Redacted 的请求。这是 02 号说的第二层。
- 不启用它的 cache 扩展，那东西会把完整回复明文落盘。
- 修掉本机 provider 走网关流式输出失败的问题。
- 钉死版本，vendor 进仓库。作者一个人维护，没有发布节奏，我们要能自己修。vendor 有配套义务：保留上游许可证，MIT 或 Apache-2.0，与我们兼容；记录 vendor 自哪个上游提交；每季度看一次上游的安全修复并择要合入；我们的修改单独成补丁文件，方便对照和回馈上游。

网关只听本机。核心与网关之间是 unix socket 加一个启动时生成的令牌，不用 TCP 端口，避免同一台机器上别的程序碰到它。

## 本机推理

Apple Silicon 上用 MLX，进程内加载，没有 Python。这是 crabllm-mlx 已经做好的部分，那个 crate 没有发布到 crates.io，只能走 git 依赖或 vendor。

### 选型

16 GB 内存决定了一切。可用的预算大约是 10 GB 给模型，其余给系统、数据库、连接器和你正在用的别的程序。

| 角色 | 第一阶段选型 | 大致体积 |
|---|---|---|
| classifier / extractor / summarizer / drafter / planner | 一个 8B 级别的 4 bit 量化通用模型 | 5 GB 上下 |
| embedder | 一个多语言小型向量模型 | 0.5 GB 以内 |

只装一个通用模型加一个向量模型，不装多个通用模型。多装一个就要在内存里换进换出，Mac mini 会开始喘。具体选哪个 8B 模型，靠评测集决定，不靠感觉。

内存更大的机器可以换 14B 甚至更大的模型，注册表里换一行。这是模型层的全部升级路径。

### 模型下载

一键。界面上显示模型名、体积、需要的磁盘空间，点一下开始，可以中断续传。下载前检查磁盘剩余，不够就说清楚要多少，不开始。这台 Mac mini 现在剩 7.7 GB 就是反面教材。

权重来源是公开的模型仓库，下载时校验哈希。注册表里每个本机模型带哈希，下载完不匹配就删掉重来。这是下载阶段唯一的网络活动，由核心执行，不经过 infer。

### 加载与驻留

通用模型常驻内存，向量模型常驻内存。空闲超过一段时间可以卸载，但下次调用要等几秒加载，所以默认不卸载。用户在设置里能看到当前内存占用。

## 云端 provider

第一阶段支持 OpenAI 兼容接口和 Anthropic 接口两种方言，这样任何主流服务商都能接。API key 存钥匙串，网关启动时取，日志里不出现。

02 号说了云端默认关闭。打开之后，用户选一个服务商、填一个 key，其余不需要配置。哪些任务能去云端、脱敏怎么做，是产品决定，不是用户配置。

## 置信度

03 号的"有条件升级"需要模型给出置信度。三种来源，按可靠程度排：

- 约束解码下的 token 概率。Constrained 协议能拿到，最可靠。
- 让模型在结构里多输出一个 confidence 字段。不太可靠，但可用。
- 规则校验的通过与否。二值，但确定。

第一阶段用第一和第三种。第二种做记录，不做决策依据。

## 评测集

模型层没有评测就没有选型依据。评测集从你自己的数据里建：

- 每个角色一组任务，100 到 200 条，输入是真实 Item，答案是你标的。
- 敏感判级的答案是你的覆盖记录，天然积累。
- 摘要与起草的答案是你改稿后的版本，也天然积累。

评测集是本机文件，不出设备。换模型时跑一遍，注册表里的 quality 字段由它填。这是 90 天计划里"评测"那块能力在这个项目里的落点。

## 成本与延迟

每个角色有延迟预算。入库流水线里的 classifier 每条要在几百毫秒内完成，否则历史导入十万封邮件要跑好几天。这决定了 classifier 必须是规则先行、模型只看剩下的少数。

云端调用记 token 与估算费用，进出境记录。用户在设置页能看到本月花了多少。

## 明确不做

- **不做微调与训练。** 分身靠的是检索你的数据做示例，不是改模型权重。07 号解释。
- **不做多设备共享推理。** Mac mini 给别的设备提供模型服务，是 P2P 那条线的事，推迟。
- **不做模型市场。** 注册表里的本机模型是我们测过的几个，不是任意 URL。
- **不支持 Intel Mac。** MLX 需要 Apple Silicon。这排除了一部分用户，第一阶段接受。

## 需要你裁决的

1. 推理与网关分成两个进程，用操作系统沙箱保证 infer 无网络。我主张分。
2. 只装一个通用模型加一个向量模型。我主张只装一个。
3. crabllm 作为 vendor 进仓库的依赖，我们自己维护修改。我主张 vendor 而不是 fork 出一个独立项目。
4. 只支持 Apple Silicon。我主张第一阶段只支持。
