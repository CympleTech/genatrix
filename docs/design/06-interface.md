# Genatrix · 界面与审批

> 状态：草稿 v0.2 · 2026-09-13 · 评审后修订，待复核
> v0.2 变更：级别标记加图标；调低级别改为内联确认；批准绑定版本；形态在 M1 结束时检验。
> 回答的问题：时间线、对话、审批面板长什么样，如何让人信任一个读过你全部数据的 AI。

## 界面要做到的一件事

让你信任它。不是靓，是可信。

信任来自四个可感知的性质，界面的每一个决定都为它们服务：

- **能看见依据。** AI 说的每句话，点一下能看到它依据的原始内容。
- **能分清事实和推断。** 哪些是你的数据，哪些是 AI 的产出，一眼可辨。
- **能看见边界。** 什么出去了、什么没出去、为什么。
- **能反悔。** 批准前能改，批准后能查，标错的能改回来。

## 形态

第一阶段是一个本地 Web 应用，核心进程提供，只听本机。菜单栏有一个状态图标，点开是浮层，显示同步状态和待批准数量，再点进浏览器。

选 Web 而不是原生窗口，理由是迭代速度。选菜单栏图标而不是 Dock 图标，理由是它应该像一个常驻的后台，不像一个要打开的 App。这个形态在 M1 结束时用真实使用来检验，不合适就换更原生的呈现，后端接口不变。

前端用 Rust 编译到 WebAssembly 的框架，保持全栈一种语言。这是一个有代价的选择，Rust 前端生态不如 TypeScript 成熟，组件要自己写得多。代价接受，理由是你的团队就是 Rust，而且这个界面不需要生态里的花活。如果三个月后发现代价过高，退路是把前端换成 TypeScript，后端接口不变。这一条列在裁决里。

## 四个面

不做多层导航。左侧四个入口，每个入口一屏。

### 今天

打开的第一屏。上面是今日摘要，中间是待批准的动作，下面是系统状态。

**今日摘要**是 03 号每日摘要流水线的产物。形态是分组的要点，不是一篇文章：

```
需要你回复（3）
  · 某人问周四能不能改到下午                        [Telegram · 昨晚 22:14]
  · 某公司发来合同修订版，等你确认第 4 条            [邮件 · 今早 08:02]
  ...
你答应过的（2）
  · 周五前把报价发给某人                            [来源 · 日期]
  ...
值得知道的（5）
  ...
```

每一行右侧是来源和时间，点击展开原始 Item。没有引用的句子标灰并注明"无依据"，这是 03 号定的。

**待批准**是审批面板的精简版，最多显示 5 条，更多去审批页。

**状态**一行：几个账号在同步、最后同步时间、本机模型是否加载、云端开关状态。

### 时间线

全部 Item 按 occurred_at 倒序。邮件和消息混排，靠来源图标区分。

筛选器只有五个：来源、人、方向、级别、时间。不做标签系统，不做文件夹。搜索框在顶部，全文加向量，结果仍然是时间线的形态，只是被过滤了。

每条 Item 的呈现：

- 作者、时间、来源、级别标记（公开、私人、机密，用三种不显眼的色点）。
- 正文是归一后的 text，点击展开可看原文（Raw 的渲染）。
- 有 Annotation 的，摘要显示在正文下方，用不同的字色和一个小标记，明确是 AI 产出。
- 被编辑过的显示"已编辑"，点开看历史版本。被上游删除的默认隐藏，筛选器里可以显示，显示时有明确标记"对方已删除，本机保留"。这是 01 号那个伦理张力的诚实呈现。

点击一个人，进入这个人的页：Handle 列表、和你的往来统计、07 号的资料卡。推断出来的合并有"推断"标记和一个"拆开"按钮。

### 对话

和 agent 的会话。它不是主入口，是补充，所以放第三位。

- 每条 AI 回复下方是它引用的 Item 列表，可展开。
- 回复中调用了工具，显示为一行折叠的步骤："搜索了 12 条消息，读取了 2 个线程"，点开是 03 号的运行记录。
- 回复中提出了动作，动作卡片内嵌在对话里，形态与审批页一致。
- 每条回复标注这次是本机完成还是云端完成，云端完成的可点开看出境记录。

不做打字机效果以外的任何拟人化。没有头像，没有名字，没有"我很高兴帮你"。它是一个工具在回答。

### 记录

三本账放一起，这是 02 号"你能审计自己的 AI"的界面。

**出境记录**第一屏是一句话和一个数字：

> 过去 7 天，0 字节机密内容离开过这台设备。有 14 次私人内容脱敏后发给了 Anthropic。

下面是列表，每条：时间、目的、级别、去向、决定。点开一条，看到实际发出的脱敏后内容，逐字。

**运行记录**：每个 Run 一条，点开是步骤。

**动作记录**：所有 Action，含已执行、已拒绝、已过期。

## 审批面板

这是整个产品里最重要的一个界面，因为 00 号第五条原则只在这里兑现。

一次一条。不做列表勾选批量批准，第一阶段不做，第二阶段的"代理"模式也是靠规则不是靠勾选。

一条待批准动作的卡片：

```
┌──────────────────────────────────────────────────┐
│ 回复邮件 → 某人 <someone@example.com>              │
│                                                  │
│ 依据                                             │
│   某人 · 今早 08:02 · "合同修订版，请确认第 4 条"    │  ← 点开看原文
│   你 · 上周三 · "第 4 条我们要求..."                │
│                                                  │
│ 为什么                                           │
│   对方等你确认第 4 条，你上周已表明立场，建议回复确认。 │
│                                                  │
│ 草稿                                             │  ← 可直接编辑
│   某人，第 4 条按上周讨论的版本，我这边确认。          │
│   ...                                            │
│                                                  │
│ 本机起草                                          │
│                                                  │
│   [ 批准并发送 ]   [ 改后再看 ]   [ 拒绝 ]           │
└──────────────────────────────────────────────────┘
```

- **依据在草稿之前。** 先看它为什么这么想，再看它想说什么。
- **草稿可直接编辑。** 改完点批准，改动成为一个新版本，你批准的就是眼前这一版，旧版本的批准对它无效。改动被记录，07 号用它学风格。
- **批准只在本机生效。** 审批请求只走本机接口，带这一版的哈希和一次性 nonce。这些你看不见也不需要看见，它们保证你点的和执行的是同一份东西。
- **拒绝要理由。** 弹出一个单行输入，可以只写两个字。理由进记录。
- **批准键上写着后果。** "批准并发送"，不是"确定"。
- **本机还是云端起草，卡片上有一行。**
- **过期倒计时。** 卡片角上一行小字"2 天后过期"。

键盘优先：上下切换，回车展开，批准与拒绝各一个快捷键，编辑进入草稿框。处理完 20 条不需要碰鼠标。

## 级别的呈现

三种级别是三个标记，每个标记是色点加一个小图标。列表里只显示标记，悬停或展开显示词和判定来源："机密 · 规则：来自银行域名"。只靠颜色不行，色觉不同的人分不出，图标是必需的，不是装饰。

调级别是点标记弹出三选一。往高调，点了就生效。往低调，选项本身写着后果：不是"私人"，而是"改为私人，之后可能脱敏后发往云端"，点这一行才生效。它不是筛选偏好，是一个有分量的动作，所以要多看一眼；但也不弹模态窗、不要求再点一次"确定"。02 号说了，说清楚，不恐吓。

## 空状态

刚装好、还没接账号的时候，四个面都是空的。空状态要说的话只有一句：接入第一个账号。之后回填进行中，时间线从上往下逐渐填满，这本身就是最好的进度反馈。

## 语言

界面中英文双语，跟随系统。你的数据是什么语言就显示什么语言，AI 产出跟随对应 Item 的语言，摘要用界面语言。

## 通知

只有一种：有新的待批准动作时，菜单栏图标上出一个数字。不推送，不弹窗，不发声。每日摘要生成后不通知，你打开的时候它在那里。

## 明确不做

- **不做移动端。** 第一阶段。
- **不做主题、皮肤、布局定制。**
- **不做标签与文件夹系统。** 五个筛选器加搜索。
- **不做批量批准。**
- **不做任何拟人化。** 没有名字、头像、情绪。
- **不做仪表盘式的图表。** 记录页是列表和一句话，不是饼图。

## 与后续文档的接口

- 01 号：已编辑、已删除的呈现；Person 页。
- 02 号：出境记录页；级别色点与调级提示；"本机完成"标记。
- 03 号：审批卡片的字段；运行记录的步骤呈现；"无依据"标记。
- 05 号：账号状态、回填进度、重新登录。
- 07 号：Person 页的资料卡；改稿与拒绝理由的采集。
- 09 号：首次运行流程复用同一套界面。

## 需要你裁决的

1. 前端用 Rust 编到 WebAssembly，接受生态代价。我倾向接受，但这是最可能反悔的决定。
2. 菜单栏图标加浏览器，而不是独立窗口。我主张菜单栏。
3. 审批一次一条，不做批量。我主张不做。
4. 没有任何拟人化。我主张没有。
5. 调低级别的确认内联在选项文字里，不弹窗。我主张这样。
